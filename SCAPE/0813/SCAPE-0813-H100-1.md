# 2. 创建最小可解释 variants

只在 upstream 实现允许的情况下构造。

必须至少有：

```text
G0 FULL
G1 GRAPH_OFF
G2 GRAPH_STATE_ONLY
G3 GRAPH_STATE_PLUS_MINIMAL_RENDER
G4 GRAPH_FULL_RENDER
```

定义：

### G0 FULL
原完整 Harness。

### G1 GRAPH_OFF
完全关闭 evidence graph。

### G2 GRAPH_STATE_ONLY
图仍然：

```text
构建
更新
持久化
```

但不把 graph-specific state / relation summary / graph hints 暴露给模型。

目的：

```text
测试 external bookkeeping 自身是否通过其他 runtime 路径产生价值。
```

### G3 GRAPH_STATE_PLUS_MINIMAL_RENDER
保留 exact graph state，只渲染：

```text
最小 claim/doc relation summary
不添加额外 heuristic instruction
不添加 future information
```

### G4 GRAPH_FULL_RENDER
保留当前完整 graph renderer。

如果 Harness-1 中 state/update/render 无法干净分离：

不要伪造 variant。

改为：

```text
G0 FULL
G1 OFF
G2 safest valid intermediate
```

并在 audit 中解释边界。

# 7. 最终只允许得到三类结论

### A. Semantic-migratable
如果：

```text
G2 << G3 ≈ G4
```

说明：

```text
graph state 需要保留
但模型使用 graph 的 semantic policy 是关键
```

这是最理想的 SCAPE hybrid case：

```text
external graph store retained
graph-aware decision -> weights
renderer/controller slimmed
```

### B. Runtime-state dominated
如果：

```text
G2 ≈ G4 >> G1
```

说明主要价值来自 runtime state/persistence。

不应强行 internalize。

### C. Renderer/scaffold dominated
如果：

```text
G3/G4 显著好于 G2
且对 renderer perturbation 很敏感
```

说明可能学的是 scaffold/template，需谨慎。
